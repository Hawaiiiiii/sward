## How the renderer chooses what to draw (Phase 354)

Each retail `.yncp` project bundles many CSD scenes. Retail's screen
state machine activates one subset at a time; rendering all of them
at once produced the chaotic overlap visible in pre-Phase-354 packs
(Title Intro showing the logo doubled, World Map's 32 scenes turning
the canvas into green stripes, Title Menu's 16 scenes stacking 5
panel rows). The mirror now drives composition through three filters
in `sgfx_ui_mirror_main.cpp`:

1. **Per-screen + per-state active-scene whitelist** (`activeScenesFor`)
   -- only scenes the retail screen state machine would have visible
   at this state are composited. State sub-cases (Pause tab, Results
   rank, Stage mode) feed into the corresponding variant.
2. **Per-cast skip list** (`castsToSkipFor`) -- a few retail scenes
   mix region-specific text casts (e.g. JP "World Adventure"
   word-mark) with shared graphical casts (Earth globe, lightning
   bolt). The EN build keeps the shared art and drops the JP text
   casts. Currently used for `title_2` only.
3. **Synthesized SetPosition anchors** (`synthesizeOverrides`) --
   Boss HUD's `su_sonic_gauge` / `gaia_gauge` / `footer` casts ship
   with anchor-relative coordinates that retail supplies at runtime
   via `CCastNode::SetPosition`. The Phase 296 SetPosition harvest
   captured anchors for Day-Sonic / Werehog HUD scenes but not these
   Boss-only ones, so SGFX seeds best-guess pixel anchors as a
   runtime-inferred fallback. (Tag: pending-Ghidra. A future
   harvest pass on the boss runtime would produce exact retail
   anchor pixels.)

## How to validate against UnleashedRecomp

1. Open each PNG in this directory.
2. Run UnleashedRecomp, navigate to the same screen.
3. Capture the screen (Win+PrintScreen or Win+Shift+S).
4. Side-by-side compare:
   - **Layout** -- panels in the right places?
   - **Asset choice** -- right textures, right CSD project?
   - **Text positions** -- captions / labels where they should be?
   - **Color / alpha** -- compositor blending matches?

Documented gaps (not bugs):

- **Text content (Phase 355 -- placeholder painter removed).** The
  Phase 346 placeholder painter that drew strings like `[help line 1]`
  and `Loading...` over the real retail textures was removed in
  Phase 355: a direct sweep of the YNCP native component map proved
  every `help_chara_*`, `help_text_area`, `progress` cast in every
  in-scope project actually has hasTexture=true and references a
  real DDS atlas. The pre-baked EN-region atlases
  (`mat_*_en_*.dds`, `fte_ConverseMain_*.dds`) come through the
  texture index automatically. Title Intro's bottom-center chunky
  text + Loading's button-label captions are the real retail
  content rendering at 640x360 (half-resolution makes them look
  pixelated). The only remaining language gap is Title Menu's
  rows: `ui_mm_contentstext.dds` ships JP-only in the base game's
  `MainMenu/` folder (the Languages/English/ tree doesn't include
  a MainMenu sub-folder) so menu labels read "ソニック・ザ・
  ヘッジホッグ" instead of "Sonic the Hedgehog". DLC packs ship a
  WorldMap-flavored EN mainmenu atlas
  (`Languages/English/WorldMap/mat_mainmenu_en_001.dds`) but it
  doesn't override the title-menu text.
- **Half-resolution canvas.** SGFX renders at 640×360 to keep the
  software CPU compositor interactive. SDL upscales to the window.
  UnleashedRecomp runs at native 1280×720; the layout is the same,
  the per-pixel resolution differs.
- **Top-left caption.** The `Title Intro`, `Stage HUD - Werehog`,
  etc. text in the corner is a Phase 346 SGFX-only debug label.
  It does not appear in retail.
- **Missing 3D content in World Map.** The black dotted rectangles
  in the stage-selector area are positions where retail renders a
  3D globe + stage thumbnails. SGFX's CSD compositor draws only the
  2D UI overlay layer; the 3D scene comes from a separate render
  graph not in scope for the UI/UX port.
- **Boss gauge L/R extensions clip.** The Sonic / Gaia gauge bodies
  render correctly but their long L/R fill extensions extend off
  the canvas because the synthesized anchors center the gauge body
  rather than the L/R rails. Real retail anchors would land the
  same way at 1280×720 since L/R are tiled fills meant to be
  clipped.

## Regenerating

```
build_mirror.bat
bin_mirror\sgfx_ui_mirror.exe ^
  --screenshots-dir=research_uiux\runtime_reference\out\sgfx_screen_validation
```

Headless (no SDL window opened); takes ~3 seconds.

## What's NOT in this pack

- Modal overlays (GeneralWindow, HelpWindow, SaveIcon, Status).
  These are reachable but only render when host opens them; not part
  of the screen graph as top-level destinations.
- Out-of-scope HUDs ported in Phase 348-351 (Mission, Boss vitality,
  Tornado Defense, MediaRoom). Those have state machines + smoke
  tests but no composite render here. The mirror could be extended
  to dump them too if needed.
- Full retail BGM (Phase 356 -- bank loader available). The mirror
  still plays the embedded `g_installer_music` OGG as a default
  fallback, but `--bgm-bank=<dir>` scans a host directory of
  pre-converted OGG cues and registers each with the audio player
  using the file name's stem as the cue name. Convert each retail
  `.csb` into an OGG with vgmstream
  (`test.exe -o <cue>.ogg <cue>.csb`) and drop the results into
  the bank dir. With a complete bank the orchestrator's
  `bgmAdmin.mountCue` drives real per-screen / per-stage BGM
  through SDL_mixer's music slot.

## In-stage popups (Phase 355)

`CHudItemGet`, the small "item picked up" popup that animates in
when the player grabs a Sun Medal / Moon Medal / continent fragment,
is now ported as `sgfx_hud_item_get.hpp`. It runs as a parallel
overlay alongside StageHud (4-phase state machine: Hidden -> Intro
-> Usual -> Outro). Mounts `game/SystemCommon/ui_itemresult.yncp`
with the retail animation tracks (`Intro_so_etf_Anim`,
`Intro_ev_etf_Anim`, `usual_etf_Anim`, `Outro_*_Anim`). Hosts
trigger a popup with `showItemGet(state, kind, mode, num, deno)`.
This popup is not visited by the validation pack capture (it's
event-triggered, not a top-level screen) but its smoke-test
coverage runs in `sgfx_smoke.exe` (23 assertions, all green).
